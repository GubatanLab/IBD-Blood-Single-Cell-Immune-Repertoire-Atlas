## Contents

This first public archive contains the manuscript's R and Python analysis workflows, 57 TCR and three BCR immuneML specifications, aggregate source outputs, seven main figures, ten supplementary figures, supplementary tables, and the dated manuscript snapshot. Scientific artifacts derive from repository commit `ce7fb869adf162607929ea2d05e8af0ed7edccc9`.

This release updates public-access and citation documentation. It does not refit scientific models or change manuscript results, figure values, or the dated Word snapshot. The current availability statement specifies NCBI GEO deposition at publication and supplies the software archive DOI.

## Reproducibility and data scope

Primary cohort expression objects, cell-level receptor sequences, participant-level clinical records, individual predictions, and trained model artifacts remain outside the repository. Shared participant labels occur in documented public external-validation derivatives. Authorized source inputs and local path configuration are required to execute the historical analysis workflows. See the reproducibility documentation and figure legends for evaluation designs and limitations.

## Review before release

The repository's existing validation tool passed. The pre-release review also examined the 15-commit history for raw-data file formats, credential patterns, source-table identifier columns, and embedded Office content. Model performance workbooks contain aggregate results; the retained Word comment is an editorial query about availability identifiers. The review found no flagged credential patterns or prohibited raw-data formats.

## Reuse and citation

The repository's existing restriction is preserved: no open-source license is granted; contact the Gubatan Lab before redistributing code or figures. Third-party materials retain their applicable terms. The software citation retains the creator listed in the original `CITATION.cff`; full paper authorship remains in the manuscript.

The Zenodo archive is uploaded from this version's Git archive, without the `.git` directory, so that the preserved files correspond to the tagged release. Future changes require a separately versioned archive for an updated software DOI.
